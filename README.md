# SheIfMent

A REST API for inventory management built with **FastAPI**, **SQLAlchemy**, and **PostgreSQL**. It supports user authentication, product CRUD, categories, tags, product filtering, and pagination.

## Features

- User registration and login with Argon2 password hashing
- JWT bearer-token authentication for protected write operations
- Product create, read, update, and delete endpoints
- Category and tag management, including many-to-many product tagging
- Product filtering by category and maximum price
- Pagination with `skip` and `limit`
- Pydantic request validation and consistent HTTP error responses
- Database schema migrations with Alembic
- Automated API tests using FastAPI's `TestClient` and an isolated SQLite test database
- OpenAPI documentation generated by FastAPI

## Tech stack

Python 3.11+, FastAPI, SQLAlchemy 2.x, PostgreSQL, Alembic, Pydantic, JWT, Argon2, pytest.

## Setup

1. Create and activate a virtual environment:

   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
   ```

2. Install dependencies:

   ```bash
   python -m pip install -r requirements.txt
   ```

3. Create a PostgreSQL database named `sheifment_db` (or choose another name), then create your local environment file:

   ```bash
   cp .env.example .env
   ```

4. Edit `.env` and set `DATABASE_URL` and a long, random `JWT_SECRET_KEY`. Do not commit `.env`.

5. Apply database migrations:

   ```bash
   alembic upgrade head
   ```

6. Start the API:

   ```bash
   uvicorn app.main:app --reload
   ```

## Main endpoints

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| POST | `/auth/register` | Public | Register an account |
| POST | `/auth/login` | Public | Get a JWT access token |
| GET | `/auth/me` | Bearer token | Get the current user |
| GET | `/products` | Public | List products; supports `skip`, `limit`, `category_id`, `max_price` |
| GET | `/products/{product_id}` | Public | Get one product |
| POST | `/products` | Bearer token | Create a product |
| PUT | `/products/{product_id}` | Bearer token | Update a product |
| DELETE | `/products/{product_id}` | Bearer token | Delete a product |
| POST | `/products/{product_id}/tags/{tag_id}` | Bearer token | Attach a tag to a product |
| GET | `/categories` | Public | List categories |
| POST | `/categories` | Bearer token | Create a category |
| PUT | `/categories/{category_id}` | Bearer token | Rename a category |
| DELETE | `/categories/{category_id}` | Bearer token | Delete an unused category |
| GET | `/tags/{tag_id}` | Public | Get a tag |
| POST | `/tags` | Bearer token | Create a tag |

For protected endpoints, use the `access_token` returned by `/auth/login` as `Authorization: Bearer <token>`.

## Run tests

```bash
python -m pytest -v
```

Tests use a separate in-memory SQLite database and do not need a running PostgreSQL server. The application itself uses the PostgreSQL URL configured in `.env`.

## Database migrations

Use `alembic upgrade head` to create/update the schema and `alembic downgrade -1` to roll back one migration. Do not use `Base.metadata.create_all()` as a substitute for migrations in a deployed environment.

## Notes

- This is a learning/CV project, not a production-hardened service. Before production use, add rate limiting, refresh-token/revocation strategy, structured logging, deployment configuration, and stronger operational monitoring.
- Never publish credentials, tokens, or `.env` files in Git history.
